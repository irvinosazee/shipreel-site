it checks its
own work.

Anything can generate a video. The question is whether you can post it without watching all twenty seconds first. Every render is measured before you ever see it:

  • Loudness mastered to −14 LUFS, so it isn't the quiet one in the feed.
  • Text legibility — every line big enough to read on a phone, held long enough to actually read.
  • Platform safe zones — nothing hidden behind TikTok's buttons or Instagram's caption bar.
  • Thumbnail baked into frame 0, so Slack, X and Discord show the frame you chose.
  • Contrast checked against WCAG on every caption and title.
  • Golden frames — a reference set that catches a render silently changing.

If a check fails, it tells you which one and why. 234 tests run on every change to the tool itself.

Release videos from git tags

Point it at a tag. It reads the release notes, or the commits since the last tag, and renders a video with the real numbers — commits, contributors, files changed — and the install command for that version. A GitHub Action attaches it to the release automatically.

Before / after clips on pull requests

It works out which pages a PR touches, captures them on production and on the preview deployment, scores the difference, and comments a labelled before/after clip. Reviewers see the change instead of imagining it.

straight answers.

There's a free tool called /brag. How is this different?

shipreel started as a fork of /brag by Shunit Haviv Hakimi, and that project is excellent — if it does what you need, use it. The difference is everything built on top: /brag is a prompt and a set of assets that tells an agent how to make one landscape video. shipreel verifies what comes out (loudness, legibility, safe zones, thumbnails, golden frames), reflows one plan across five frame sizes and 26 platforms, captures your running UI, cites every on-screen claim to a file in your repo, and ships release videos, PR previews, a GitHub Action and a standalone CLI. 36 scripts and 234 tests, where the original had one script and none.

Does it upload my code anywhere?

No. It reads your repo locally and renders locally. There is no shipreel server, no account, and no telemetry in the skill. The only network calls are the ones your own tools make — fetching Hyperframes to render, and fetching GitHub or npm numbers if you ask for live metrics.

Can I use the videos commercially?

Yes — they're yours, with no royalty, no watermark and no credit to shipreel required. The bundled music is CC BY 4.0 by Sascha Ende, so if you use it, credit him: every launch kit writes that line into credits.txt for you. Sound effects are CC0 by Kenney.

What exactly am I licensed to do?

Use and modify it for one developer, or for everyone at one company, forever. You can't redistribute or resell the source, or offer it as a competing hosted service. Two carve-outs sit above that: the upstream MIT portions stay MIT, and the bundled audio stays under its own licence.

What if it breaks?

It renders through Hyperframes, FFmpeg and Chrome, which all move independently — so it can break. A nightly job renders a real composition against the latest Hyperframes so breakage surfaces within a day rather than when you need a video. If something's broken for you, email me; if it's unusable, take the refund.

Do I need Claude Code?

No. The CLI path needs no agent at all — it reads your package metadata, README and git history, captures your site, and fills a clean template. An agent gets you a video written for your specific project rather than a filled-in template, which is better, but it's not required.
