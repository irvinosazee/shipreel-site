shipreel --help

straight answers.

There's a free tool called /brag. How is this different?

shipreel is a fork of /brag by Shunit Haviv Hakimi, and that project is good: if it does what you need, use it. Both are free; the difference is what sits on top. /brag is a prompt and a set of assets telling an agent how to make one landscape video. shipreel verifies what comes out, reflows one plan across five frame sizes and 26 platforms, captures your running interface, cites on-screen claims to files in your repo, and adds release videos, PR previews, a GitHub Action and a standalone CLI. One script and no tests became 36 scripts and 260.

Does my code leave my machine?

No. It reads your repo and renders locally; there is no shipreel server and no account. shipreel itself sends nothing. Be aware that the tools it drives have their own behaviour: Hyperframes is fetched from npm to render and reports anonymous usage of its own, and live-metrics mode calls GitHub or npm because you asked it to.

Can I use the videos commercially?

Yes. No royalty, no watermark, no credit to shipreel required. The bundled music is CC BY 4.0 by Sascha Ende, so credit him if you use it; every launch kit writes that line into credits.txt for you. Sound effects are CC0 by Kenney. Don't register a render that contains the music with YouTube Content ID; that licence forbids it.

Why is it free?

Because a tool that reads your private repository should be one you can read too, and because I would rather a lot of people use it than a few pay for it. It is MIT: use it, fork it, ship it inside your own product. If it saves you an evening, a star on GitHub is the whole price.

What if it breaks?

It drives Hyperframes, FFmpeg and Chrome, which move independently of it, so it can. A nightly job renders a real composition against the current Hyperframes, so breakage shows up within a day rather than when you need a video. If it's broken for you, open an issue, or send the fix, it's open source.

Do I need Claude Code?

No. The CLI reads your package metadata, README and git history, captures your site, and fills a clean template with no agent at all. An agent writes something made for your project instead of a filled-in template, which is better, but it isn't required.

How do I hear about new versions?

On GitHub, Watch → Custom → Releases on the repo and you get one notification per release, video included. To follow what I build next: GitHub, LinkedIn, or Medium.
